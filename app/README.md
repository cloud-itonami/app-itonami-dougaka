# dougaka Studio — Tauri v3 (Awai Android)

`app/` is the Tauri v3 shell that ships the real dougaka Studio UI
(`../site/studio-host.js` — generation modes, jobs, local management —
plus the scittle timeline-plan app in `../site/app.cljk`) in a WebView.
It is not a blueprint viewer: `npm run build` assembles `dist/` from the
repo's own `site/` and `src/` sources, verbatim.

- package id: `network.itonami.dougaka` (`package.json` `itonami.id`,
  `src-tauri/tauri.conf.json` `identifier`)
- Tauri: `3.0.0-alpha.6` (CLI devDependency; shell crates pinned `=3.0.0-alpha.6`)
- Network: the page calls `https://generation.murakumo.cloud` directly
  from the WebView, through the vendored canonical consent broker
  (`vendor/kotoba-client-runtime.js`, per-operation consent). No
  operation is pre-approved; the broker rejects undeclared operations.
  The CSP `connect-src` names exactly that origin plus the Tauri IPC
  bridge. Browser-local management state stays in localStorage behind
  the same broker (no fetch).

## Build

```sh
export PATH="$HOME/.cargo/bin:$PATH"          # Homebrew rustc lacks the android target
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
export ANDROID_HOME=$HOME/Library/Android/sdk
export NDK_HOME=$HOME/Library/Android/sdk/ndk/27.0.12077973
npm ci            # in app/
npm run build     # static build into app/dist/
npm test          # build + node --test (vendor pins, dist contents, CSP)
npm run build:android   # scripts/android-apk.sh: init + debug APK (aarch64)
npm run build:android -- x86_64 debug    # Desktop QA APK
npm run build:android -- x86_64 release  # Desktop release-build input for signing
npm run build:android -- aarch64 release
```

Install the matching Rust target (`aarch64-linux-android` or
`x86_64-linux-android`). Each command builds one architecture and checks that
the generated APK contains the corresponding dougaka native library before
printing its SHA-256.

`src-tauri/gen/` is generated by `tauri android init` and is not
committed; delete it and re-run `tauri android init --ci` if it breaks.
`src-tauri/tauri.js` is the shim the generated Android buildSrc needs
(`node tauri …` with `src-tauri` as cwd).

## Vendor pins

`vendor/PINS.json` records sha256 for the client runtime + consent CSS
(the exact `site/site.edn` `:client-runtime` pin), the pinned
`kotoba.lang.text` source (`:external` pin), and the DADS stylesheet.
`scripts/build.mjs` refuses to build on pin drift. Provenance for each
file is in `PINS.json` `provenance`.

## Limits (Stage 1)

- Store signing and production deployment are separate release steps.
- The shell HTML (`src/index.html`) mirrors `site/dougaka/page.cljk`
  (same mounts, script order, CSP) because the web site build
  (`scripts/build-site.cljk`, kbb + sibling checkouts) cannot run at
  APK build time. If `page.cljk` changes, update the shell to match.
- Icons are the Tauri placeholder set from the series template.
